# Package 模块体验

> Package 模块的目标不是展示仓库库存，而是帮助用户回答：哪些还没到、哪些已归属且可合箱、哪些有问题、哪些已进入某次 Shipment。它是 P01 所观察到的多订单核对与到仓确认摩擦的主要承接处。

## Package List

### 用户要完成的判断

1. 哪些 Package 还在等待到仓？
2. 哪些已到仓但还未确认归属或可处理？
3. 哪些现在可加入 Shipment？
4. 哪些有 Exception，或已被其他有效 Shipment 占用？

### 列表最小信息

| 信息 | 为什么必要 |
| --- | --- |
| 简短 Package 识别信息 | 让用户区分多件 Package；不必展示冗长仓内字段。 |
| 国内运单号（可截断展示） | 与预报和国内物流核对相关。 |
| 当前状态及用户语言说明 | 直接回答是否到仓、是否归属、是否能合箱。 |
| 最近更新时间 / 最近事件 | 帮助用户判断状态是否新鲜，而不承诺实时。 |
| 可选性 | 明确可选择、不可选择，或已在某个 Shipment。 |
| Exception 标记与原因摘要（如有） | 避免用户把异常 Package 误当作遗漏。 |

### 状态筛选

V1 使用任务导向筛选，不为每个内部状态制造单独入口：

```text
全部｜等待到仓｜待确认｜可合箱｜已加入转运｜需处理
```

- `等待到仓`：`DECLARED`、`INBOUND_TO_WAREHOUSE`
- `待确认`：`ARRIVED_PENDING_MATCH`
- `可合箱`：`READY_FOR_SHIPMENT`
- `已加入转运`：`IN_SHIPMENT`
- `需处理`：`EXCEPTION`

## Package Detail

Package Detail 只提供帮助用户判断和行动的信息，按以下层级组织：

1. **当前状态与下一步：** 如“仓库已收货，正在确认归属；当前无需操作”。
2. **预报与识别信息：** 国内运单号，以及最小商品证明/信息。
3. **到仓 / 归属事件：** 已预报、在途、仓库收到、可合箱等事实和时间。
4. **相关凭据：** 仅在可用时展示验货或商品照片；照片是 P1 凭据，不覆盖主要状态。
5. **可用操作：** 根据状态显示查看、编辑可更正信息、加入 Shipment 或查看关联 Shipment。
6. **Exception：** 若有，提升至顶部，说明影响、下一步和支持入口。

不展示货位、内部操作员、完整仓库扫描日志、与当前决策无关的技术字段。

## Package Selection：多件合箱体验

P01 的单次 10–20 件 Package 场景意味着选择不能依赖用户逐条记忆。选择体验必须是 Package List 的一种任务模式，而非独立“购物车式”功能。

### 选择规则

| 情况 | 是否可选 | 产品处理 |
| --- | --- | --- |
| `READY_FOR_SHIPMENT` | 可选 | 允许加入本次 Shipment 选择集合。 |
| `DECLARED` / `INBOUND_TO_WAREHOUSE` | 不可选 | 展示“尚未到仓”的原因，不隐藏该 Package。 |
| `ARRIVED_PENDING_MATCH` | 不可选 | 展示“仓库已收货，等待归属/处理确认”。 |
| `EXCEPTION` | 不可选 | 展示问题摘要并进入 Package Detail 处理。 |
| `IN_SHIPMENT` | 不可选 | 显示已关联的 Shipment，并可跳转查看。 |

### 批量选择机制

1. 用户从 `可合箱` 筛选进入选择模式；
2. 只允许对 `READY_FOR_SHIPMENT` 进行多选；
3. 固定显示“已选择 X 件”和继续创建 Shipment 的入口；
4. 保留未选择的可用 Package 数量，让用户意识到还有哪些物品留到下次；
5. 提交前显示已选 Package 的汇总与不可选 Package 的原因入口；
6. 选择不会立即改变 Package 状态；只有提交 Shipment 后才变为 `IN_SHIPMENT`。

### 防止遗漏，而不是替用户决定

V1 帮用户盘点，不自动把所有可用 Package 全部合箱。是否等待后续到仓、是否排除某件商品是用户决策。系统提供：

- 可合箱、待确认、仍在途的数量；
- 已选 Package 清单；
- 未选但可用的 Package 清单；
- 不可选原因。

系统不提供“智能推荐现在必须合箱”的结论，因为当前没有足够研究或业务规则支持该判断。
