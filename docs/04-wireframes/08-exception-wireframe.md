# Exception 低保真结构

> Business Exception 不是技术加载失败，也不是一句无上下文的“请联系客服”。它必须绑定具体 Package 或 Shipment，说明影响、用户责任和当前处理进度。以下场景用于 V1 模拟演示，不宣称为已验证的真实业务政策。

## 通用结构

```text
┌──────────────────────────────────┐
│ [需要处理 / 正在处理]              │
│ <与 Package 或 Shipment 关联的标题>│
├──────────────────────────────────┤
│ WHAT HAPPENED                     │
│ 已知事实；原因未知时明确“正在核实” │
├──────────────────────────────────┤
│ IMPACT                            │
│ 影响哪一件 Package / 哪次 Shipment │
│ 当前无法进行哪一步                 │
├──────────────────────────────────┤
│ WHAT YOU NEED TO DO               │
│ 明确动作，或“当前无需操作”          │
│ [执行指定动作]                     │
├──────────────────────────────────┤
│ CURRENT PROGRESS                  │
│ 等待你的信息 / 正在处理 / 已解决    │
│ 最近更新：<事件时间>               │
├──────────────────────────────────┤
│ SUPPORT                            │
│ 如仍需人工：携带 Reference 与问题摘要│
│ [查看支持方式]                     │
└──────────────────────────────────┘
```

异常仅作为关联实体 Detail 内的条件区块呈现，不创建无上下文的“异常中心”。Technical Error（例如加载失败）只提供重试，不改变 Package 或 Shipment 的业务状态。

## V1 模拟场景

| Scenario | 关联对象与影响 | What happened | What you need to do | Current Progress / 恢复 |
| --- | --- | --- | --- | --- |
| Package 无法匹配用户 | Package；不可加入 Shipment | Warehouse 已收货，但暂未确认归属。 | 按提示补充订单截图或最小商品信息。 | 等待用户信息；核对后回到“已到 Warehouse，正在确认归属”或“可合箱”。 |
| Package 信息异常 | Package；阻塞归属确认 | 预报信息与收货核对信息不足或不一致。 | 查看具体缺少项并更正必要信息。 | 等待补充；不提供无边界的通用编辑。 |
| Shipment 无法继续处理 | Shipment；暂停 Warehouse Processing / 出库 | Warehouse 处理发现影响本次 Shipment 的问题；具体原因按模拟 Scenario 填写。 | 若页面列出明确要求则完成；否则当前无需操作。 | 处理完成后回到 Warehouse Processing 或相应等待状态。 |
| Payment Failure | Shipment；不可出库，回到待付款 | 本次模拟 Payment 未确认成功。 | 检查结果后重新发起模拟付款。 | 付款失败已确认；恢复“最终报价已生成，请确认并付款”。 |
| Tracking Exception | Shipment；暂停国际运输或清关推进 | 最近运输事件显示需要进一步核实；不假设具体承运商或原因。 | 当前无需操作，或按明确指引提供信息。 | 正在处理；解决后恢复原运输阶段或下一阶段。 |
| UK Last-mile Exception | Shipment；影响签收 | 英国本地派送未按正常路径完成，正等待进一步状态。 | 查看页面给出的具体下一步；必要时使用带 Reference 的支持指引。 | 正在核实 / 等待用户动作；解决后恢复英国派送或更新签收。 |

## 状态分层

| 当前进展 | 用户应看到 | 用户是否要行动 |
| --- | --- | --- |
| 等待你的信息 | 缺少或需更正的具体信息、提交入口 | 是，只做明确指向的动作 |
| 正在处理 | 已知影响、最近更新、预计恢复阶段（如可知） | 否；明确写“当前无需操作” |
| 已解决 | 问题已解决、恢复到的状态 | 依恢复状态决定，例如付款或等待出库 |

## Actionable 支持

需要人工协助时，支持区块至少提供：

- 关联实体类型与 Reference / 国内单号末位；
- 一句可复制的问题摘要；
- 当前 Exception 状态与最近更新时间；
- 项目演示中定义的支持方式。

这不是完整客服系统，也不默认将用户转去人工沟通；只有无法自助完成、或规则明确要求人工介入时才展示。

## 异常页面边界

- 不展示未经验证的赔付、退款、清关法规、承运商责任或处理时效承诺。
- 不允许用户仅靠点击“已解决”自行恢复业务状态。
- Exception 解决后恢复合适的 Package / Shipment 主流程状态，不把 Exception 当作终态。
