# 竞品与替代方案分析框架

> 本文只定义研究框架，不包含任何具体品牌、产品功能或优劣结论。尚未执行联网研究、注册体验或用户验证，因此不得把本框架中的维度填成具体竞品事实。

## 分析目标

竞品分析不是为了罗列功能，而是回答：目标用户目前用什么方式完成中国 → 英国寄送？每种方式在哪些任务上足够好、在哪些交接处仍需要人工、记录或重复查询？

研究结果应与用户访谈交叉验证。公开页面能说明服务方声称提供什么，不能证明用户真实使用频率、满意度或体验质量。

## 对象分类

| 类别 | 定义 | 研究问题 | 当前结论 |
| --- | --- | --- | --- |
| Direct Competitor | 面向个人用户、提供中国集货至英国跨境寄送/集运相关服务的产品或服务入口 | 是否覆盖从仓库地址到签收的核心任务？信息和交易在哪里断裂？ | 未研究，不填写具体对象/结论 |
| Indirect Competitor | 可替代部分任务的服务，例如单件国际快递、跨境电商直邮、承运商追踪工具或其他寄送平台 | 用户为何选择它而不选择集运？它在哪一段减少或增加摩擦？ | 未研究，不填写具体对象/结论 |
| Manual Alternative | 用户通过人工与分散工具自行完成流程的组合 | 用户用什么手工步骤弥补系统缺口？成本在哪里？ | 候选形式待访谈验证 |

### Manual Alternative 候选形式

以下不是已观察到的行为，而是后续需验证的候选替代组合：

```text
微信人工客服
+ 电商订单页 / 国内快递查询
+ Excel、备忘录、聊天收藏或截图
+ 独立物流网站查询
```

## 比较维度

| 维度 | 需要观察什么 | 记录要求 |
| --- | --- | --- |
| 国内仓地址获取 | 用户如何获取、复制和填写仓库地址；是否有用户识别规则/引导 | 截图/链接、访问日期、是否需登录、信息缺口 |
| 包裹预报 | 是否支持预报；何时需要；需要哪些字段；是否有成功反馈 | 区分公开说明、实际体验与未确认项 |
| 包裹列表 | 用户能否看见自己的 Package；字段、筛选、状态和历史如何表达 | 记录用户可见信息，不推断后台能力 |
| 到仓通知 | 触发时点、渠道、内容、是否可追溯 | 区分站内消息、订阅消息、人工通知 |
| 合箱 | 用户如何选择 Package、是否说明可选/不可选原因、能否修改 | 记录约束、操作成本和是否需要人工 |
| 增值服务 | 是否有验货、拍照、加固、去包装等选项及其说明 | 不将“有入口”推断为用户高需求或服务质量高 |
| 重量展示 | 是否展示实重、体积/计费重量、测量时间和差异说明 | 记录透明度，不评判价格是否合理 |
| 报价 | 报价在何时出现、展示何种费用/时效/限制、是否有有效期 | 标记公开报价、询价、支付前报价或未知 |
| 支付 | 支付入口、付款状态、失败/退款说明、支付与出库关系 | 不记录或暴露敏感支付数据 |
| 国际物流追踪 | 状态层级、最后更新时间、来源、国际单号/事件可见性 | 记录具体可观察事件与时间，不把宣传语当实时能力 |
| 清关状态 | 是否向用户显示清关阶段、需用户行动的提示和资料要求 | 不推断清关模式、税费或合规责任 |
| 英国末端配送 | 是否说明末端交接、派送和签收信息 | 区分服务承诺与可实际查询的事件 |
| 异常处理 | 是否有问题入口、异常说明、进度、用户所需动作 | 记录可观察流程，不能只根据 FAQ 推断真实 SLA |
| 客服依赖程度 | 哪些任务必须通过人工完成，客服入口和响应承诺如何表达 | 需结合用户访谈，不能只从页面判断 |
| 信息透明度 | 用户能否在各阶段知道当前事实、下一步、时间和来源 | 用具体任务评估，而非主观“页面好看” |

## 任务驱动比较方法

与其只比功能表，更应执行同一组可观察任务：

1. 第一次找到中国仓地址并理解如何填写；
2. 记录一件国内包裹并确认是否到仓；
3. 判断哪些 Package 可以一起提交；
4. 理解称重后的价格与付款下一步；
5. 在已出库后确认国际、清关、英国派送或签收状态；
6. 找到并理解一个异常处理入口。

对于每个任务，记录完成条件、步骤数、需要切换的工具、信息缺失、是否被迫联系人工以及不确定之处。结论应写为“在本次可观察体验中”，而非“该产品总是”。

## 输出纪律

- 每个具体事实都需要来源、访问日期和研究方法；网页文案、实际试用和用户口述应分开记录。
- 不把“没有找到”写成“产品没有”；应写成“在本次公开/试用范围内未观察到”。
- 不以竞品存在某项功能直接证明用户需要它；用户研究仍是需求优先级的主要证据。
- 不收集不必要的真实订单、地址、支付或追踪敏感数据。
