# 真实用户 Discovery Interview：研究计划

> 研究状态：已完成一位独立真实用户 P01 的探索性访谈。本文件保留研究目标、假设和方法；下表状态仅反映 P01 的单样本证据，不表示广泛验证。P01 收敛与边界见 [../../hypothesis-validation.md](../../hypothesis-validation.md)。

## Research Objective

本轮研究通过回放近期真实的中国 → 英国寄送/集运经历，理解用户实际行为、工具、信息来源、决策点与困难。重点验证：

1. 谁是真正高价值的核心用户；
2. 用户为什么选择中英集运；
3. 是否真的存在多 Package 合箱需求；
4. 用户当前如何管理多个国内包裹；
5. 到仓状态是否存在信息问题；
6. 合箱流程是否存在摩擦；
7. 用户最关心价格的哪个阶段；
8. 报价、支付、出库是否容易理解；
9. 国际运输过程中用户最关注什么信息；
10. 什么情况下用户会主动联系客服；
11. 异常处理最大的痛点是什么；
12. 微信小程序是否是合理的用户入口。

研究目标是识别他们已经在做什么、在哪里被阻断、如何绕过问题，以及哪些假设不成立。

## Research Questions

| 研究问题 | 需要观察的真实证据 |
| --- | --- |
| 谁是高价值用户？ | 最近 12 个月实际寄送次数、包裹数量、任务复杂度、痛点强度、是否重复发生 |
| 为什么选择集运？ | 当时的触发情境、考虑过的替代方式、实际选择理由 |
| 多 Package 管理是否是问题？ | 包裹数、商家/快递来源、记录工具、遗漏/重复/等待决策 |
| 状态、合箱、报价和支付是否构成摩擦？ | 用户实际查询/提交/付款过程、困惑、停顿、人工支持触发点 |
| 履约追踪与异常信息是否不足？ | 出库后查询行为、所需状态、客服记录、真实异常案例 |
| 微信小程序是否适配？ | 用户在不同任务中实际使用的入口、设备和工具偏好，不是抽象态度 |

## Participants

### 建议样本

建议完成 **4–6 名独立真实用户**的半结构化访谈。这个数量只适合个人作品集的方向性 Discovery，不能用来推断市场规模或统计显著性。

优先筛选：

- 最近 12 个月有中国 → 英国集运或个人寄送经历；
- 使用过淘宝、拼多多、京东或其他中国电商/寄送渠道；
- 有多个包裹合箱经验者优先，但也保留至少一名单包裹或未合箱用户作为反例；
- 愿意按时间顺序复盘一次真实经历。

### 建议记录字段

只记录与研究相关的非敏感信息：

- 匿名编号，例如 `P01`–`P06`；
- 用户类型（自述/研究分类）；
- 最近寄送时间的大致范围；
- 大致使用频率；
- 最近一次大致包裹数量；
- 使用的工具类型和服务类型。

不记录真实姓名、联系方式、精确地址、完整运单、支付凭据、身份证件、聊天内容或可识别个人的信息。原始联系人信息如因招募需要存在，应保留在仓库外，不进入公开 GitHub。

### Self Journey / Researcher Experience

研究者本人可以单独记录一份 **Self Journey / Researcher Experience**，用于：

- 识别研究问题和候选假设；
- 练习旅程复盘与记录格式；
- 形成待与独立样本比较的反例或线索。

它不与独立访谈样本等价，不计入“4–6 名独立用户”，也不能单独验证任何假设或支持泛化结论。

## Method

| 项目 | 计划 |
| --- | --- |
| 方法 | 10-15 分钟半结构化访谈，以最近一次真实经历回放为主 |
| 访谈形式 | 线上语音/视频或线下；记录方式需先征得同意 |
| 核心材料 | [02-interview-guide.md](02-interview-guide.md)、[03-interview-note-template.md](03-interview-note-template.md) |
| 分析方式 | 将原始记录转为 Observation → Pain Point → Need → Pattern → Product Insight；详见 [05-synthesis-framework.md](05-synthesis-framework.md) |
| 假设追踪 | 逐份记录回填至 [06-hypothesis-validation-table.md](06-hypothesis-validation-table.md)，不在样本不足时提前下结论 |

## Research Quality Guardrails

- 访谈只记录真实经历；若用户没有经历某环节，记录“未发生/无法回忆”，不补全为假想流程。
- 主持人不展示产品方案、不解释预设状态机、不暗示“正确”答案。
- 每条候选结论要同时记录支持证据、反例和样本限制。
- 受访者的具体身份和可识别信息不得进入公开文档。
- 访谈完成后仍以 `Insufficient Evidence` 为默认保守结论，直到存在足够一致、具体且可追溯的证据。
