# P01 访谈洞察

> 本文从一位匿名受访者 P01 的结构化访谈材料中提炼观察与洞察。原始访谈材料不纳入公开仓库；所有内容仅描述 P01 的真实经历或由该经历导出的有限产品含义；不外推为所有中英转运用户的行为。

## Observed Behaviors

1. P01 约每 3 个月进行一次转运；最近一次将约 10–20 个来自多个中国电商渠道的 Package 集中寄往英国。
2. P01 从客服获取带专属姓名、编号和电话的仓库地址，并主动提交订单截图与国内运单号，以便仓库识别商品和归属。
3. 国内物流显示送达后，P01 仍会主动询问客服，确认仓库已实际收到并归入个人集合；其描述通常一天内可以确认。
4. P01 人工逐一核对电商订单是否漏件、错件或尚未送达，再决定是否开始合箱。
5. P01 会根据“暂时没有更多购买计划”、Package 是否到齐来决定合箱；可以排除部分 Package，并在封箱前修改选择。
6. P01 会为易碎品选择加固、为占空间的包装选择去包装；一般选普通运输，有急需物品时选特快。
7. P01 用客服发送的验货、物品总览和分层装箱照片确认商品状态和打包过程。
8. P01 在封箱称重、确认报价后付款；费用和计费重量对其而言清楚易懂。
9. P01 在国际段使用全球物流查询网站和客服，在英国段使用新的 Royal Mail 单号；曾因状态长期显示“派送中”而电话联系客服。
10. 因服务方没有网站或 App，P01 的到仓、离仓和打包重量查询依赖微信客服；中英时差下回复有时需等待数小时。

## Pain Points

| Pain Point | Evidence | User Impact |
| --- | --- | --- |
| 国内物流签收后，Package 是否真正入仓并归属自己仍不可直接确认 | P01 在国内物流显示送达后仍要向客服确认；其说明仓库包裹多，客服未必能自然识别归属。 | 用户需要等待并发起人工沟通，才能判断 Package 是否可纳入后续计划。 |
| 多个订单的完整性需要人工跨工具核对 | P01 需要查看所有电商订单，确认有无漏件、错件或未送达，并明确评价人工核对“很麻烦”。 | 决定何时合箱前存在额外核对成本；本例没有实际漏件/错件。 |
| 关键仓库状态依赖人工客服，且受时差影响 | P01 所用服务没有网站/App；到仓确认、离仓和重量查询需找微信客服，有时等待数小时。 | 信息和操作不能按用户需要即时完成，特别是在付款后等待离仓时。 |
| 英国末端状态异常时，用户只能另行联系承运商 | P01 曾遇到 Royal Mail 长时间显示“派送中”、超过预计时间；最终通过电话客服解决。 | 用户需要自己判断何时升级处理并切换支持渠道；异常原因和解决细节尚未获得。 |

## Workarounds

| 目标 | P01 当前做法 | 局限 |
| --- | --- | --- |
| 让仓库识别自己的 Package | 主动提交订单截图和运单号；国内物流送达后再次询问客服。 | 仍依赖人工确认；是否每件均必须预报尚未确认。 |
| 确认本次可寄商品是否齐全 | 人工查看电商订单，再参考客服发送的物品/验货照片。 | 跨多个信息源核对；本例尚无漏件/错件结果。 |
| 确认打包、报价和出库 | 等客服照片、称重报价和后续回复；付款后向客服查询离仓。 | 无法自行及时查询，受客服响应与时差影响。 |
| 查询履约与处理派送问题 | 国际段看物流网站/问客服，英国段改用 Royal Mail 单号；延迟时电话联系 Royal Mail。 | 需要切换信息源和支持渠道；异常处理细节仍未知。 |

## Key Insights

1. **“国内签收”不是 P01 可结束关注的节点。** 对 P01 而言，只有确认 Package 已被仓库收货并归属个人后，Package 才可进入可计划的集合。该洞察由 P01 直接支持，仍需验证是否适用于其他服务模式。
2. **P01 的核心自助诉求是关键仓库状态，而非更多人工沟通入口。** 到仓确认、打包重量、是否离仓是其点名的优先查询事项；说明信息可得性和时效本身是产品机会。
3. **合箱在 P01 的旅程中是一项主动的 Shipment 决策。** 用户会控制包含哪些 Package、何时发出、选择何种服务，并可在封箱前修改。该证据支持 Package → Shipment 的业务模型，但未证明所有用户都觉得该操作困难。
4. **报价是付款决策节点，但价格不透明不是 P01 的问题。** P01 会核对重量、单价和人工打包费后支付，且认为其清晰；产品应先确保可解释的报价信息，而非预设复杂的价格教育是首要痛点。
5. **异常体验需要区分“正常追踪”和“无法行动”。** P01 认为新旧单号切换清楚；真正需要升级处理的是英国派送长时间未按预计到达的例外情况。

## New Findings

以下发现补充了此前的候选问题，但同样只观察于 P01：

- **照片是信任与核对凭据。** 验货、物品总览和分层装箱照片帮助 P01 确认商品状态和打包过程。
- **增值服务存在具体触发条件。** 易碎品对应加固、占空间包装对应去包装、急需物品对应特快；它们不应被设计成无差别的功能堆叠。
- **用户可接受费用透明，但仍需要看到费用事实。** P01 清楚重量、单价和小额人工打包费，表明报价表达的目标可以是“可核对”，而不必假设“必然复杂”。
- **离仓存在用户可理解的服务承诺。** P01 所用服务承诺付款后 3 天内离仓；该规则不能外推为产品事实，需作为外部业务假设保留。
- **当前可观察到的是“数字化自助需求”，而不是“小程序偏好”。** P01 提到网站或 App 会更方便，尚未对微信小程序作比较选择。
