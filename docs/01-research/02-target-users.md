# 目标用户假设

> 以下对象均为 **Product Assumption**，由“可能存在中国至英国个人寄运需求”这一问题空间推导而来，并非已完成用户访谈、市场调研或业务数据分群的结论。V1 是否只服务其中一类、三类是否共享同一核心任务，须验证后决定。

## 候选用户总览

| 候选用户 | 选择原因 | 当前证据状态 |
| --- | --- | --- |
| 英国中国留学生 | 可能在英国生活期间购买中国商品，并可能出现多包裹集中寄送场景 | Product Assumption |
| 长期居住英国的华人个人用户 | 可能有持续的中国商品购买、家庭收件或亲友寄送需求 | Product Assumption |
| 高频购买淘宝/拼多多等中国电商商品的用户 | 多店铺、多国内快递可能使包裹管理和合并决策更复杂 | Product Assumption |

不在本阶段假定跨境卖家、代购或企业客户是目标用户。这些人群的批量、库存、财务和履约需求可能显著不同，会使 0→1 范围失焦。

## 英国中国留学生

| 维度 | 假设分析 |
| --- | --- |
| 使用背景 | 在英国学习、居住，可能需要从中国购买生活、学习或节日相关商品。**Product Assumption** |
| 使用场景 | 在多个中国电商店铺下单后，等待包裹在中国仓汇集，再寄往英国。**Product Assumption** |
| JTBD | 当我在中国购买的商品来自多个商家、最终需要寄到英国时，我想知道哪些包裹已经到仓、能否一起寄以及要付多少钱，从而用可预期的方式完成一次寄送。 |
| 核心需求 | 获取仓库信息；预报并确认包裹；选择要合并的包裹；确认价格并支付；查看后续进度。以上均为 Product Assumption。 |
| 核心痛点 | 多个国内单号难整理；到仓/可发状态不明；价格与时效不确定；状态异常时不知道找谁。均待验证。 |
| 使用频率 | 可能围绕开学、换季、节日或集中购物出现；具体频率、季节性和包裹数均待验证。 |
| 最关注的信息 | 包裹是否到仓、是否遗漏、可否合箱、最终费用、预计到达、异常影响。均为 Product Assumption。 |

## 长期居住英国的华人个人用户

| 维度 | 假设分析 |
| --- | --- |
| 使用背景 | 在英国长期生活，可能因家庭消费、兴趣商品或亲友寄送而需要中国至英国的包裹服务。**Product Assumption** |
| 使用场景 | 重复使用转运服务，可能需要寄往固定或少量英国收件地址。**Product Assumption** |
| JTBD | 当我需要把中国来源的物品寄到英国时，我想在一个可信入口中完成包裹管理、费用确认和进度查询，从而减少重复填写与不确定沟通。 |
| 核心需求 | 清楚的服务限制、可靠的地址信息、费用说明、履约状态和问题处理入口。均待验证。 |
| 核心痛点 | 地址/收件信息重复填写；对安全、签收、清关或延误的担忧；异常时缺少可追踪处理。均待验证。 |
| 使用频率 | 可能为低至中频的重复需求；是否比留学生更重视地址复用或服务可靠性，待验证。 |
| 最关注的信息 | 服务可用性、价格/时效、安全性、英国派送与签收、异常后的处理进度。均为 Product Assumption。 |

## 高频购买中国电商商品的用户

| 维度 | 假设分析 |
| --- | --- |
| 使用背景 | 在一定时间内从淘宝、拼多多等多个店铺购买商品，可能产生多家国内快递和多个运单。**Product Assumption** |
| 使用场景 | 希望将同时到达或分批到达的多个包裹集中管理，并决定本次何时提交转运。**Product Assumption** |
| JTBD | 当我有多个正在前往或已到中国仓的包裹时，我想快速盘点、选择和提交本次要寄出的包裹，从而避免遗漏并降低重复操作。 |
| 核心需求 | 高效的包裹清单、状态辨识、合箱选择、地址/偏好复用和历史回看。均待验证。 |
| 核心痛点 | 单号多、包裹多、状态分散；不清楚哪些已可发；担心重复选择或漏选；每次重复填写。均待验证。 |
| 使用频率 | 可能为中至高频；“高频”的具体定义应由近期开单/寄送行为确定。 |
| 最关注的信息 | 当前包裹总览、到仓完整性、可合箱范围、费用、操作效率。均为 Product Assumption。 |

## 优先验证的问题

1. 哪一类用户有最强、最稳定且最适合自助化的任务？
2. 用户现在如何解决从中国到英国的包裹问题，替代方案在哪里失效？
3. 多包裹合并是否真实高频且足够痛，还是只是可能存在的业务动作？
4. 价格、时效、安全、服务限制、状态透明度和便利性中，哪些真正决定选择？
5. 用户是否愿意使用微信小程序完成关键动作，尤其是预报、付款与异常处理？
