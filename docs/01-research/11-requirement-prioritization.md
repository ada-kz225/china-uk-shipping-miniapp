# 第一轮需求优先级分析

> 这是基于当前 Discovery 的**暂定优先级**，不是已验证路线图。优先级从“用户是否能完成一次中国 → 英国的个人集运闭环”出发，而非从功能数量或实现难度出发。若 [08-validation-plan.md](08-validation-plan.md) 中的关键假设被推翻，本表必须调整。

## 优先级标准

| 等级 | 标准 |
| --- | --- |
| P0 | 缺少该能力，用户无法完成候选核心闭环中的必要任务，或无法知道交易/履约是否真正完成。 |
| P1 | 不阻塞最小闭环，但明显降低重复操作、不确定性、异常沟通或信任成本。 |
| P2 | 增强体验、增长或增值服务；在核心任务、业务规则和外部数据尚未验证前不应优先投入。 |

## P0 用户需求（暂定）

1. 获得并正确使用中国集货仓收件信息；
2. 让国内 Package 被可靠归属，并查看自己的 Package 与到仓/可操作状态；
3. 从可用 Package 中选择组合，提交含英国收件信息的 Shipment；
4. 在仓库处理后确认计费重量和报价；
5. 确认支付结果，并知道何时已出库；
6. 从出库到英国签收获得最小、连续的阶段状态；
7. 遇到阻断异常时知道影响、下一步和处理状态。

## P1 用户需求（暂定）

- 在关键状态变化时被主动提醒；
- 重复使用时复用地址；
- 查看到仓/验货凭据；
- 选择有真实仓库能力支撑的增值服务；
- 在自助信息不足时获得上下文明确的人工支持。

## P2 用户需求（暂定）

- 获得优惠/促销激励；
- 获得积分或会员回馈。

## 明确不进入本轮 P0 的事项

- 复杂仓库任务、客户管理、承运商调度和财务对账；
- 多国家、多线路、多币种和自动化方案比价；
- 完整赔付、退款审批、复杂售后和企业账户；
- AI 问答、预测、路线优化；
- 为丰富作品集而添加、却无法解除核心任务阻塞的能力。

## 重新排序触发条件

以下任一发现应触发重新排序，而不是继续按当前表开发：

- 多 Package 合箱并非高价值真实任务；
- 用户无需主动预报即可被可靠匹配；
- 支付/出库顺序与当前候选模型不同；
- 用户不将微信小程序作为合适入口；
- 真实路线无法提供报价、支付或履约事件数据，且演示边界不能诚实表达。
