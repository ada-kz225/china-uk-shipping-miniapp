# 问题分析

> 以下是待验证的候选问题，并非研究结论。每个问题都需要通过真实用户访谈、任务回放、可用业务记录或可用性测试确认其发生频率、影响强度和现有替代方案。

## 对候选问题的判断

这些候选问题具有合理性，因为它们位于跨主体、跨地域、跨状态的交接处；但“合理”不等于“最值得解决”。例如：

- 多包裹合箱可能是少数用户场景，而非普遍需求；
- 用户可能已有成熟的服务商应用或客服群，状态不透明未必是主要痛点；
- 价格敏感可能超过状态透明，也可能恰好相反；
- 微信小程序可能不是用户偏好的入口；
- 清关与运输异常虽影响大，但可能发生频率很低，更适合先做信息/支持入口而不是复杂自助系统。

因此，优先级必须由“出现频率 × 任务阻断程度 × 现有替代方案不足 × 产品可解决性”共同决定，而非由功能想象决定。

## 建议收敛的 5 个问题

在尚未获得研究证据前，建议以以下五项作为最值得验证、也最可能构成首版价值的**候选问题**：

1. **包裹到仓与可操作状态不透明。** 用户是否无法确定“是否到仓、是否能合箱、现在该做什么”？
2. **多 Package 的统一管理与一次 Shipment 的选择困难。** 用户是否真的会因为多个包裹而产生遗漏、等待和选择成本？
3. **称重后的报价、付款与出库之间缺乏清晰决策链。** 用户是否不清楚费用怎么来、何时付、付完后会发生什么？
4. **跨境履约进度缺乏可理解的连续信息。** 用户是否需要区分仓库处理、出库、国际运输、清关、末端派送和签收？
5. **异常发生时缺少可行动的自助信息。** 用户是否因不知道问题影响/下一步而高度依赖人工沟通？

## 不作为当前优先问题的候选

- 优惠、会员、裂变、内容运营：尚无证据证明其比完成基本履约更重要。
- 多承运商自动比价：需先取得真实方案和价格数据，否则容易制造伪精确。
- AI 助手、预测、路线优化：没有经过验证的数据、任务或评估基线。
- 仓库作业、客户管理、财务对账：属于运营侧能力，不等于用户端核心问题。
