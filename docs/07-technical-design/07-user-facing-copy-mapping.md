# 用户可见文案映射

> 用户端所有内容使用中文。内部状态码可以出现在 API、日志、测试和本表的左列，但小程序渲染层只能消费右侧中文字段，禁止直接显示 code。

## 1. Package

| Internal State | 中文状态 | 中文说明 | 中文下一步 |
| --- | --- | --- | --- |
| `DECLARED` | 已预报，等待送往仓库 | 已收到你的预报信息，这不代表包裹已经到仓。 | 当前无需操作；包裹送达仓库后会进入确认流程。 |
| `INBOUND_TO_WAREHOUSE` | 正在送往仓库 | 包裹正在前往中国仓，尚未完成收货与归属确认。 | 当前无需操作。 |
| `ARRIVED_PENDING_MATCH` | 已到仓，正在确认归属 | 仓库已记录收货，正在确认包裹是否归入你的包裹集合。 | 当前无需操作；如需补充信息会明确提示。 |
| `READY_FOR_SHIPMENT` | 可合箱 | 包裹已确认归属，可以选择加入本次转运单。 | 可选择加入本次转运单，也可以继续等待其他包裹。 |
| `IN_SHIPMENT` | 已加入本次转运 | 该包裹已锁定在关联转运单中，不能再次选择。 | 查看关联转运单，了解处理和运输进度。 |
| `EXCEPTION` | 需要处理 | 此包裹暂时不能按正常流程继续。 | 请查看具体影响和下一步；如无需操作会明确说明。 |

| --- | --- | --- | --- |
| `DRAFT` | 正在准备本次转运 | 已选择部分包裹，但尚未提交给仓库。 | 调整包裹、填写英国收货地址后提交。 |

| `AWAITING_PAYMENT` | 最终报价已生成，请确认并付款 | 已生成本次最终计费重量、费用项和总价。 | 核对报价后确认并模拟付款。 |

| `INTERNATIONAL_TRANSIT` | 国际运输中 | 转运单正在跨境运输中。 | 当前无需操作；可查看最近运输进度。 |
| `CUSTOMS_CLEARANCE` | 清关中 | 转运单正在清关阶段。 | 默认无需操作；如需配合会明确提示。 |
| `UK_LAST_MILE` | 英国派送中 | 转运单已进入英国本地派送阶段。 | 当前无需操作；等待签收或按异常指引处理。 |
| `DELIVERED` | 已签收 | 已收到签收事件，本次转运已完成。 | 无需操作；可查看完整记录。 |
| `EXCEPTION` | 需要处理 | 当前问题影响转运单继续推进。 | 查看发生什么、影响什么和明确下一步。 |
| `CANCELLED` | 已取消 | 本次转运在实际出库前已取消。 | 查看相关包裹；需要时重新创建转运单。 |

## 4. Exception structure

每个业务异常必须返回下列中文字段；不能只返回“异常”或内部原因码。

| Field | 用户端标题 | Content rule |
| --- | --- | --- |
| `userWhatHappened` | 发生什么 | 仅陈述已知事实；未知时写“正在核实”。 |
| `userImpact` | 影响什么 | 明确影响哪件包裹或哪一阶段。 |
| `userNextAction` | 你需要做什么 | 要么给可执行动作，要么明确“当前无需操作”。 |
| `userProgress` | 当前进展 | 例如“正在核实”或“等待补充信息”。 |
| `userSupport` | 需要帮助 | 上下文明确的支持方式；不展示技术信息。 |

## 6. Implementation guard

- 建立唯一的 `copyMap` / presenter；页面不自行 hard-code 英文状态；
- API 契约测试验证每个状态均有中文 `title`、`explanation`、`nextAction`；
- Error middleware 负责把未处理错误转换为中文通用提示，内部明细仅写日志；
- Code review 检查所有 UI 字符串，不允许将 `READY_FOR_SHIPMENT`、`PAID_AWAITING_DISPATCH` 等内部码直接放入页面。
