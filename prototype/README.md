# 中英集运小程序 V1 低保真可点击原型

## 目的

本目录是用于验证 V1 任务流、状态表达和交互逻辑的独立低保真原型。它不属于正式微信小程序生产代码，也不代表真实仓库、支付或物流系统已经接入。

## 如何运行

无需安装依赖或启动服务：

1. 在文件管理器中打开 [index.html](index.html)；
2. 使用本地浏览器直接打开；
3. 在手机宽度窗口中体验，或使用浏览器的移动设备模拟模式。

原型只使用本目录内的 HTML、CSS 和 JavaScript 文件，不依赖框架、网络请求或构建工具。

## 已实现的 7 个 P0 页面

1. 首页
2. 包裹
3. 包裹详情
4. 预报包裹
5. 转运
6. 创建转运单
7. 转运单详情

最终报价、模拟付款、运输进度、英国收货地址和异常信息均保留在“转运单详情”上下文中，不增加独立页面。

## 可演示任务流

### Happy Path

1. 从“首页”进入“包裹”；
2. 在 15 条模拟包裹中查看待到仓、待确认、可合箱、已转运和需处理状态；
3. 点击“开始合箱”，从 10 件可合箱包裹中选择 8 件；
4. 确认固定底栏显示“已选择 8 件”“还有 2 件可合箱包裹未选择”；
5. 创建转运单，填写英国收货地址并提交；
6. 在转运单详情使用“原型演示控制”依次模拟仓库处理、最终报价、付款、实际出库、国际运输、清关、英国派送和签收。

### Exception Path

- 在“包裹”筛选“需处理”，查看“包裹信息待确认”；
- 在“转运”打开“英国派送信息待核实”的转运单；
- 检查异常是否包含发生什么、影响什么、你需要做什么、当前进展和支持信息；
- 使用标注为“原型演示控制”的模拟运营事件查看恢复主流程的效果。该控制不是正式用户功能。

## 模拟数据与边界

原型含有：

- 15 条包裹数据：2 件待确认、10 件可合箱、1 件已加入转运、1 件需处理、1 件待到仓；
- 6 张初始转运单：待仓库处理、待付款、已付款待出库、国际运输中、已签收、需处理；
- 模拟中国仓收货 / 匹配 / 打包 / 称重 / 出库事件；
- 模拟付款结果；
- 模拟国际运输、清关、英国派送和签收事件。

这些模拟替代的是外部数据来源和运营事件，**不替代**包裹与转运单的核心状态约束：

- 只有“可合箱”包裹可以被选择；
- 一件包裹提交后只属于一张有效转运单；
- 付款成功不等于已从仓库发出；
- 已从仓库发出不等于已签收；
- 用户不能自行将业务问题标记为已解决。

## 文案与范围

- 所有实际界面文案为中文；内部状态码仅存在于脚本逻辑中，不会直接展示。
- 原型不包含会员、优惠券、积分、真实支付、真实物流接口、自动读取电商订单、完整客服或完整仓储后台。
- 视觉仅使用基础卡片、列表、按钮、底部导航和状态强调；重点是任务完成能力，而非品牌或高保真 UI。

## Usability Validation

- 原型已完成 1 次真实 exploratory usability test，参与者以匿名编号 UT01 记录；
- 多包裹合箱、判断是否已出库、查看当前物流进度、异常处理 4 个核心任务均已测试；
- 根据真实测试反馈，已完成两项交互优化：多选后保留滚动位置；已选包裹的“移除”操作固定在每行右侧；
- UT01 的 Task 1 定向回归中，用户自主连续选择 8 件包裹时未再回顶，且能直接找到右侧“移除”；未发现新的阻塞问题。
- 单一样本不代表广泛用户结论；本次结果属于 exploratory usability testing。
